# NoticiasCol Home V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Ejecución directa en esta rama; no se requiere delegación.

**Goal:** Construir Home V2 modular con apertura automática fotográfica/tradicional, instrumentación obligatoria en el dataLayer existente, optimización obligatoria de Next.js/Core Web Vitals y auditoría/eliminación segura de código muerto, preservando Home actual y páginas internas durante el A/B desactivado hasta autorización.

**Architecture:** Composición editorial en Server Components, datos coordinados mediante clientes modulares existentes y configuración de secciones tipada. Islas cliente limitadas a interacción, medición visible y multimedia; eventos enriquecidos mediante `GAEvent`/`GAPageView`, sin otro transporte. Home actual se conserva como control, con asignación estable preparada pero apagada y caché que no mezcle variantes.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind 4/Radix, WordPress/WPGraphQL, clientes de `src/lib/api`, caché existente, `next/image`/SafeImage, dataLayer/GTM, Jest, Playwright, Storybook y Knip ya presentes.

**Spec:** [Goal y requisitos](../../home-v2/GOAL.md), [referencia visual](../../home-v2/reference.jpg), [contrato analítico](../../home-v2/analytics.md), [protocolo de rendimiento](../../home-v2/performance.md), [auditoría de limpieza](../../home-v2/dead-code-audit.md).

## Global Constraints

- El Home V2 utiliza el dataLayer existente. No implementar tracking paralelo ni integrar nuevamente GA4 desde cero.
- No introducir eventos antes de auditar implementación, convenciones, GTM/GA4, consentimiento, navegación y duplicación.
- Los clics están asociados al módulo editorial y las impresiones representan contenido realmente visible, con deduplicación documentada.
- Atribución a experimento `home_v2`, variante `control`/`v2`, módulo, posición, artículo y componente; tratamiento `photographic`/`traditional` independiente de A/B.
- Objetivos p75 de usuarios reales: LCP ≤ 2,5 segundos, INP ≤ 200 ms, CLS ≤ 0,1. No presentar resultados de laboratorio como mediciones reales de usuarios.
- Línea base antes de implementar; comparar control y V2 en móvil/escritorio. No aprobar una regresión significativa sin documentar su causa y resolverla o justificarla explícitamente.
- Optimización e instrumentación durante el desarrollo; código muerto se audita desde el inicio y solo se elimina tras verificar uso real y pruebas.
- No eliminar componentes/estilos exclusivos del Home actual durante el A/B; preservar páginas internas, anuncios, rutas dinámicas y build.
- El experimento A/B permanece desactivado hasta recibir autorización explícita. No desplegar ni activar tráfico real desde este plan.
- No enviar información personal identificable ni crear identidad de lector propia. Respetar consentimiento y modo demo/QA.
- Consultar Context7 y documentación local de la versión instalada antes de usar APIs de librerías/CLI. No cambiar stack, CMS ni plataforma de despliegue para realizar V2.

## Review Focus

1. Consentimiento tardío, GTM diferido y remontajes no deben perder contexto ni duplicar vistas (fases 1 y 6).
2. Filtros/responsive/BFCache no fabrican impresiones; solo contenido real visible tiene denominador (fases 4 y 6).
3. Una segunda noticia precargada o añadida sin verse no cuenta como apertura; sesión expirada no hereda atribución (fase 6).
4. Datos/imágenes ausentes y errores parciales conservan jerarquía, dimensiones y frescura sin cascada de solicitudes (fases 3, 5 y 8).
5. Asignación/caché y limpieza no filtran V2 al control ni rompen categoría, anuncios o rutas dinámicas (fases 9 y 10).

Contratos compartidos a implementar en `types.ts`:

- `HomeVariant = 'control' | 'v2'`; `OpeningTreatment = 'current' | 'photographic' | 'traditional'`.
- `HomeSectionConfig`: `id`, `categorySlug`, `position` (1-based), `presentation`, `limit`, `href`, `includeDescendants`. IDs estables definidos en el mapa de eventos; validar posiciones/IDs únicos.
- `HomeV2Data`: `featured: PostHome | null`, `sections` por ID con artículos normalizados, `regions` con jerarquía de taxonomías y errores parciales tipados. No enviar cuerpos completos de artículos para tarjetas.
- `composeHomeSections(data: HomeV2Data, config: readonly HomeSectionConfig[])`: modelo puro ordenado, con deduplicación editorial por ID/URI, sin red.
- `getHomeV2Data(): Promise<HomeV2Data>`: consultas coordinadas y caché explícita; los componentes reciben resultados, no instancian clientes independientes.
- `selectOpeningTreatment(featured: PostHome | null): OpeningTreatment`: regla inicial para V2: imagen editorial con URL válida → `photographic`; sin imagen → `traditional`. Preservar selección de noticia destacada vigente; no inferir un campo CMS fotográfico inexistente. Error de imagen mantiene reserva y fallback tradicional; registrar el tratamiento efectivamente presentado sin repetir page view.
- `HomeMeasurementContext`: propiedades tipadas de `analytics.md`. `GAEvent`/`GAPageView` aceptan contexto opcional; nunca obligatorio para consumidores antiguos.
- `resolveHomeVariant(enabled: boolean, assignment: HomeVariant | null): HomeVariant`: `control` si está apagado o no hay asignación válida. QA fuerza variantes solo en entorno de pruebas autorizado; no es elegibilidad de experimento.
